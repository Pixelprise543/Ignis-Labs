# Design: live NASA data for Ask Ignis (2026-11-15)

## Problem

1. The production Vercel deployment answers `POST /api/si` with a 500:
   `ERR_MODULE_NOT_FOUND: Cannot find module '/var/task/src/lib/siFallback'`.
   Vercel transpiles `api/si.ts` per file instead of bundling, so extensionless
   ESM imports and the `@/` alias reach Node unrewritten. Deep links
   (`/app/explore`) also 404 because there is no `vercel.json` rewrite.
2. Ask Ignis answers only from the 20 baked-in experiments. The user asked for
   the chatbot to reach real NASA databases, preferring NASA APIs.

## Decisions

| Decision | Choice | Why |
| --- | --- | --- |
| Model provider | none | Keeps the honesty story; every sentence is data or a cited report. |
| Function runtime | Edge (`export const config = { runtime: 'edge' }`) | Vercel bundles edge functions, so alias/extension resolution cannot fail. |
| Literature source | NTRS `https://ntrs.nasa.gov/api/citations/search` | Keyless, returns title, abstract, report number, PDF link, centre, year. |
| Browser access to NTRS | through our own `/api/nasa` proxy | NTRS sends no `Access-Control-Allow-Origin`, so the browser cannot call it directly. |
| Offline / GitHub Pages | baked snapshot `data/nasa/ntrs.ts` | No server functions there; the panel still works, labelled with the snapshot date. |
| Where NASA data appears | a panel under the chat answer, not inside `SIResponse` | `SIResponse.citations` are experiment ids rendered as `CitationChip`s; NTRS ids must not enter the contract or the citation audit. |
| Quoting rule | report titles + verbatim abstract excerpts + links | An abstract is NASA's words, never converted into a metric, score or finding. |
| Images | `images-api.nasa.gov` (CORS-open) | Optional second step; costs no proxy. |

## Architecture

```
Drawer --askSI--> POST /api/si --> offlineAnswer()        (unchanged, deterministic)
   |
   +--findNasaPublications(question)--> GET /api/nasa?q=  (edge proxy, 6h cache)
                                         |-- NTRS search
                                         +-- fallback: data/nasa snapshot
```

`src/lib/nasa.ts` is the only module that knows about NTRS. It validates the
proxy response with zod, caps the query at 120 characters, times out at 4 s and
**never throws**: any failure returns the snapshot with `source: 'snapshot'`.

## Honesty

- Live results carry `retrievedAt` (ISO) from the proxy response; the panel says
  "Live from NASA NTRS, retrieved <date>".
- Snapshot results say "NASA NTRS snapshot, <date>"; the date is generated by the
  sync script, never hand-written.
- A report is labelled by its `stiType` and report number. It is never described
  as one of the 20 experiments in the dataset.
- No result means the panel is not rendered at all (no empty frame, no "0 results"
  theatre).

## Delivery order

M0 production fix (edge + rewrite) → M1 proxy + client → M2 snapshot →
M3 drawer panel. M4 (imagery) only if the first four are green.
